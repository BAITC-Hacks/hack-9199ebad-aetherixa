# AI Sana — Город решений

MVP для хакатона: бизнес превращает короткое описание проблемы в подтверждённую
карточку, а студенческие команды выбирают задачи и отправляют предложения.
Рейтинг показывает полноту описания задачи. Бизнес вручную выбирает одну,
несколько или ни одной команды.

## Запуск в PyCharm

Откройте всю папку `Hackathon`, выберите интерпретатор `.venv/Scripts/python.exe`.
В терминале из корня проекта выполните:

```powershell
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

- Сайт: <http://127.0.0.1:8000/>
- Swagger API: <http://127.0.0.1:8000/docs>
- Проверка процесса: <http://127.0.0.1:8000/health>

В проект добавлена конфигурация запуска PyCharm `AI Sana` и файл `run_local.cmd`.
Они запускают то же приложение. Одновременно используйте один способ запуска:
два процесса не могут занимать один порт.

**Не нужно отдельно запускать Flask и старый `server.py`.** FastAPI раздаёт сайт,
CSS, JavaScript и API с одного адреса; браузер обращается к относительным `/api/...`.
Дополнительная настройка CORS для этого варианта не нужна.

## База данных

По умолчанию используется SQL Server Express:

```text
DB_SERVER=DESKTOP-D5H3SMJ\SQLEXPRESS
DB_NAME=aetherix_backend
DB_DRIVER=ODBC Driver 17 for SQL Server
```

Требуются работающий SQL Server и установленный ODBC Driver 17. Приложение
подключается от Windows-пользователя, запустившего Python. Если база ещё не
создана, выполните в SSMS:

```sql
IF DB_ID(N'aetherix_backend') IS NULL
BEGIN
    CREATE DATABASE aetherix_backend;
END;
```

При необходимости скопируйте `.env.example` в `.env` и измените настройки:

```powershell
Copy-Item .env.example .env
```

Не выполняйте копирование поверх уже настроенного `.env`. Пустое значение
`DATABASE_URL` означает использование SQL Server из настроек `DB_*`.

Схема приложения едина: `app/models.py` и `app/ui_models.py`. При запуске
выполняется миграция существующей схемы backend и создание недостающих таблиц.
Старые карточки без отметки подтверждения требуют повторного подтверждения;
это не удаляет их тексты. Первоначальная база `aetherix_db` из отдельного
`database_schema.py` имеет другую структуру и не используется этим приложением.
Перед обновлением ценной SQL-базы сделайте её резервную копию в SSMS.

`database_schema.py` в корне теперь вызывает создание той же единой схемы,
а не старые независимые модели. Его отдельный запуск необязателен.

## Проверка без SQL Server

Для самостоятельной локальной демонстрации доступен `run_demo.cmd`. Он явно
использует отдельный SQLite-файл `aisana-demo.db` и локальную обработку по правилам.
Этот режим не переносит данные из SQL Server и не заменяет его настройки.
В PyCharm ему соответствует конфигурация `AI Sana Demo`.

Альтернатива в отдельном терминале PowerShell:

```powershell
$env:DATABASE_URL = 'sqlite:///./aisana-demo.db'
$env:AI_FORCE_FALLBACK = 'true'
python -m uvicorn app.main:app --reload
```

Для возврата к SQL Server откройте новый терминал без этих переменных либо:

```powershell
Remove-Item Env:DATABASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:AI_FORCE_FALLBACK -ErrorAction SilentlyContinue
```

## Основной сценарий

1. Представитель бизнеса вводит короткий черновик.
2. Помощник предлагает уточняющие вопросы; вопросы сохраняются в базе.
3. Бизнес отвечает и получает редактируемую карточку с семью полями.
4. После проверки текста бизнес явно подтверждает публикацию. Только теперь
   начисляется рейтинг за заполненные поля.
5. Задача появляется в каталоге, списке и городе. Можно фильтровать по теме
   и уровню готовности, сортировать по рейтингу или дате.
6. Студент выбирает команду и отправляет идею, план, срок и ссылку на прототип.
7. Бизнес рассматривает отклики и вручную выбирает или отклоняет команды.
8. Команда отправляет результат этапа миссии, бизнес подтверждает его.
   Опыт и монеты начисляются за подтверждение; повторное действие не выдаёт
   повторную награду за тот же этап той же команде.

Редактирование опубликованной карточки снимает подтверждение: её нужно
проверить и опубликовать заново. Низкий рейтинг **опубликованной** задачи
не запрещает отклик. Статус публикации и уровень рейтинга «черновик» — разные
показатели.

## Формула рейтинга

За непустое поле подтверждённой карточки начисляется его полный вес.
Это прозрачная оценка заполнения, а не ML-оценка истинности или качества текста.

| Поле | Баллы |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи решения | 10 |
| Контакт и формат взаимодействия | 10 |

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая,
90–100 — приоритетная. Опыт команды и магазин на этот рейтинг не влияют.
Высота здания показывает готовность карточки, а не выполнение проекта.

## AI и данные

`app/ai_service.py` содержит интеграцию Anthropic Messages API: анализ
черновика и сборку карточки. Чтобы включить внешний AI, заполните в `.env`
`AI_API_KEY`, `AI_MODEL` и при необходимости `AI_BASE_URL`. Используйте модель,
доступную вашему API-аккаунту. Ключ остаётся на backend.

Модели передаются текст текущей задачи и ответы пользователя. Подключение к
SQL Server и вся база данных модели не передаются. Обучения собственной модели
нет. Prompts запрещают добавление фактов; результат проверяется по формату,
а бизнес проверяет факты перед публикацией.

Без ключа, при недоступности API или некорректном ответе включается
детерминированная локальная заглушка. Интерфейс показывает этот режим, API
возвращает `ai_used=false` и причину. Это не работа обученной локальной AI-модели.
Локальная обработка ищет явно подписанные поля и предложения с признаками
сведений о данных, результате, ограничениях и других разделах. Сведения,
которые она не смогла уверенно распознать, остаются недостающими: пользователь
уточняет их ответами или вручную в карточке. Такой разбор ограничен правилами
и не заменяет понимание текста языковой моделью.
Структурная проверка JSON не может гарантировать отсутствие выдуманных фактов.

При `SEED_DEMO=true` добавляются 5 исходных черновиков, 5 опубликованных
карточек разной полноты, 5 команд и 5 предложений с идеей, планом, сроком
и демонстрационной ссылкой. Все семь полей рейтинга присутствуют в схеме,
но у менее готовых карточек часть полей намеренно пуста.
Команды, предложения и бизнес-задачи из этих примеров не являются реальными.
Ссылки `example.com` обозначают вымышленные прототипы и не ведут к готовым
решениям. Инициализация отмечается в базе; повторный запуск не восстанавливает
уже изменённые пользователем демонстрационные записи.
Пользовательские записи и ответы сохраняются в выбранной базе.

Полные инструкции модели: `ANALYZE_SYSTEM_PROMPT` и `ASSEMBLE_SYSTEM_PROMPT`
в [app/ai_service.py](app/ai_service.py). Форматы запросов доступны в
[Swagger](http://127.0.0.1:8000/docs) и `app/schemas.py`. Готовые примеры
входных/выходных данных и объяснение обработки ошибок приведены в
[DEMO.md](DEMO.md#входные-и-выходные-данные-помощника).

## Архитектура и технологии

Python 3.11+, FastAPI, Uvicorn, SQLAlchemy, Pydantic, HTTPX, python-dotenv,
pyodbc; SQL Server для основной базы, SQLite для изолированных тестов и demo.
Интерфейс — HTML, CSS, JavaScript и SVG-дома. Flask для объединённого запуска
не требуется.

```text
app/main.py          — сайт, static и регистрация API
app/database.py      — подключение и сессии
app/models.py        — карточки, команды, отклики, вопросы и прогресс
app/ui_models.py     — режимы и размещение задач
app/migrations.py    — совместимое обновление схемы backend
app/ai_service.py    — промпты, API модели и локальная заглушка
app/rating.py        — веса и расчёт рейтинга
app/progress.py      — награды за подтверждённые этапы
app/routers/         — HTTP-операции
frontend/templates/index.html — единая страница
frontend/static/     — стили, SVG-представление города и API-клиент
tests/               — проверки сценариев на отдельной временной базе
```

`frontend/models.py` остался как исторический набор данных макета и не
используется объединённым сайтом. Данные экрана загружаются через API.

## Проверка для жюри

Используйте [пятиминутный сценарий с готовыми текстами](DEMO.md).
Он показывает исходное описание, уточняющие вопросы, опубликованную карточку
с 20 баллами, исправление недостающих полей и рост до 100 баллов, затем
предложение команды и ручной выбор бизнеса. Установка и запуск выполняются
до начала демонстрации.

Автоматические проверки:

```powershell
python -m unittest discover -s tests -v
```

Тесты используют временную SQLite-базу и подменяют внешний AI-вызов; основную
SQL-базу и платный API они не изменяют.

Автоматические проверки покрывают сценарии на SQLite, обновление старой
схемы, компиляцию схемы SQL Server и миграцию индекса на моделируемых
метаданных. Актуальное количество и результат выводит команда выше.
Реальное подключение и миграция
SQL Server требуют проверки из вашей Windows-сессии: процесс проверки Codex
не получил доступ к Windows-аутентификации SQL Server. Внешний запрос к
Anthropic без предоставленного API-ключа не выполнялся.

## Ограничения

- Это локальный MVP без полноценной регистрации, паролей и серверного
  разграничения прав. Переключение «Бизнес / Студент» демонстрирует сценарий,
  а не подтверждает личность. Публиковать API в интернет в таком виде не следует.
- Внешний AI требует собственного ключа и доступности сервиса; без него
  демонстрируется обозначенная заглушка.
- Нет чата, уведомлений, загрузки файлов и производственной инфраструктуры.
- Существующий маршрут миссии относится к задаче; это не отдельный проектный
  трекер с независимым маршрутом для каждой выбранной команды.
- Публичная deployed-версия не создана. Локальный адрес работает на компьютере,
  где запущено приложение; доступ по LAN зависит от сети и настроек компьютера.
