# AI Sana: демонстрация жюри за 5 минут

Все названия, числа, материалы и предложения ниже — вымышленные данные для
демонстрации. Они не являются результатами исследования или достигнутыми
бизнес-показателями. Время установки и запуска в пять минут не входит.

## Подготовка до защиты

1. Установите зависимости по README. Запустите только одно приложение:
   `run_demo.cmd` или конфигурацию PyCharm `AI Sana Demo`.
2. Откройте [сайт](http://127.0.0.1:8000/) и
   [Swagger](http://127.0.0.1:8000/docs). Демонстрация использует отдельную
   SQLite-базу и локальную обработку по правилам; SQL Server для неё не нужен.
3. Выберите демо-роль «Бизнес». Подготовьте этот файл рядом с браузером,
   чтобы копировать значения. При повторной репетиции создавайте новую
   карточку, например с суффиксом «— повтор 2»; удалять базу не требуется.
4. В отдельной вкладке редактора откройте `app/ai_service.py`, где находятся
   два промпта. До демонстрации выполните `python -m unittest discover -s tests -v`.
   Тесты используют временную базу и не обращаются к платному API.

Честно обозначьте режим: «Интеграция с внешней моделью предусмотрена. Сейчас
покажем разрешённый локальный режим по правилам; надпись в интерфейсе и
`ai_used=false` это подтверждают».

Не нужно за пять минут проходить все этапы миссии или финальную проверку.
Основной обязательный путь заканчивается предложением и ручным выбором бизнеса.

## Тексты для копирования

### Исходная задача

Название:

```text
Демо жюри — очередь в кофейне
```

Категория:

```text
ритейл
```

Исходное описание:

```text
Контекст: В кофейне посетители долго стоят в очереди.
```

После сборки первая версия должна содержать только контекст и шесть пустых
полей. Если модель или правила выделили что-то иначе, это видно в редактируемой
карточке: приведите её к указанной первой версии до подтверждения. Не вводите
«нет данных» в неизвестные поля — оставьте их пустыми, поскольку рейтинг
проверяет заполнение, а не смысл таких заглушек.

### Полная карточка для повышения рейтинга

Название можно сохранить. Во время редактирования заполните поля:

| Поле | Текст |
|---|---|
| Контекст и потребность | В кофейне посетители долго стоят в очереди. |
| Данные и материалы | Предоставим учебную таблицу из 20 заказов с номером и временем выдачи. |
| Ожидаемый результат | Нужен работающий прототип экрана очереди заказов. |
| Критерии успеха | На 10 тестовых заказах можно добавить заказ, увидеть его номер и отметить выдачу. |
| Ограничения | На прототип есть 3 дня. Интеграция с кассой не требуется. |
| Пользователи | Бариста и посетители кофейни. |
| Связь с бизнесом | Представитель кофейни отвечает на вопросы в чате команды и проверяет демонстрацию. |

Подтверждённые веса: `20 + 20 + 15 + 15 + 10 + 10 + 10 = 100`.
Это полнота представленного описания, не доказательство качества решения.

### Предложение команды

| Поле | Текст |
|---|---|
| Идея | Сделаем экран очереди, на котором бариста меняет статус заказа, а посетитель видит свой номер. |
| План | Согласуем сценарий, создадим прототип, проверим его на 10 учебных заказах и покажем бизнесу. |
| Срок в днях | 3 |
| Ссылка на прототип | https://example.com/coffee-queue-demo |

Адрес `example.com` — обозначение вымышленного прототипа. Не выдавайте его
за deployed-решение. Поле ссылки необязательно; можно оставить его пустым.

Если показываете первый этап миссии, пример результата:

```text
Для учебного сценария описаны два пользователя: бариста меняет статус заказа, посетитель смотрит номер на экране. Требуется подтверждение бизнеса.
```

## Входные и выходные данные помощника

Это примеры контракта API. Идентификаторы назначает база; формулировки вопросов
и набор распознанных полей зависят от текста и используемого режима.

Запрос `POST /api/ai/analyze`:

```json
{
  "draft_text": "Контекст: В кофейне посетители долго стоят в очереди."
}
```

При работе с уже сохранённой карточкой запрос также содержит `task_id`.
Ниже сокращённый пример структуры ответа: показаны три вопроса из набора.

```json
{
  "task_id": 42,
  "ai_used": false,
  "fallback_reason": "Включён локальный демонстрационный режим без обращения к AI.",
  "covered_fields": ["context_need"],
  "missing_fields": ["data_sources", "expected_result", "success_criteria", "constraints", "users", "contact_format"],
  "questions": [
    {"field": "data_sources", "question": "Какие данные или примеры заказов вы можете предоставить?"},
    {"field": "expected_result", "question": "Какой конкретный результат должна передать команда?"},
    {"field": "success_criteria", "question": "Как вы проверите, что результат решает проблему?"}
  ]
}
```

Запрос сборки `POST /api/ai/assemble` — используйте настоящий `task_id`
и текст вопросов, полученный на предыдущем шаге:

```json
{
  "task_id": 42,
  "draft_text": "Контекст: В кофейне посетители долго стоят в очереди.",
  "answers": [
    {
      "field": "data_sources",
      "question": "Какие данные или примеры заказов вы можете предоставить?",
      "answer": "Предоставим учебную таблицу из 20 заказов."
    }
  ]
}
```

Ответ содержит `task_id`, `ai_used`, `fallback_reason`, `title` и `fields` с
семью строковыми полями карточки. В этом примере появились контекст и данные;
прочие неизвестные сведения должны оставаться пустыми. Карточка сохраняется
черновиком; вызов AI не публикует её и не начисляет официальный рейтинг.

### Где показать промпты и обработку ошибок

- `app/ai_service.py`, `ANALYZE_SYSTEM_PROMPT`: определить покрытые/недостающие
  поля и вернуть от 3 до 5 вопросов без новых фактов.
- Там же, `ASSEMBLE_SYSTEM_PROMPT`: собрать семь полей только из описания
  и ответов пользователя; неизвестные сведения оставлять пустыми.
- `_call_model`: обрабатывает сетевые ошибки и невалидный JSON с ограниченным
  числом попыток. Если корректный ответ получить не удалось, включается
  обозначенная локальная обработка.
- Проверка результата отклоняет некорректную структуру, неизвестные поля,
  неверные типы и неподходящее количество вопросов. Корректный JSON сам по
  себе не гарантирует истинность фактов — перед публикацией текст проверяет бизнес.
- `tests/test_integration.py`: проверяет некорректные ответы модели, локальный
  режим, сохранение вопросов/ответов, подтверждение и отсутствие автоматической
  публикации. Реальный платный AI-вызов в этих тестах заменён.

Во время пятиминутной защиты достаточно показать место промптов и назвать
поведение при ошибке. Полный разбор входных/выходных примеров можно оставить
для вопросов жюри. Внешний AI без ключа и реальное SQL Server-подключение
в локальной демонстрации не проверяются.
